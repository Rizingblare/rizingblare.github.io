1,157개 개념을 위한 지식 위키 v2 구조

개념 목록을 바로 문서화하지 않고 inventory, canonical catalog, 작성 작업 큐로 분리한 이유를 기록합니다.

게시 2026.08.03갱신 2026.08.03
GitHub PagesKnowledge WikiStatic SiteMulti-agent

문서를 만들기 전에 개념을 먼저 식별합니다

1,157개 목록은 독립 문서, 용어집 항목, 비교 문서, 표준, 법규, 시사 항목이 섞여 있습니다. 따라서 목록의 한 줄을 곧바로 하나의 게시글로 만들지 않습니다.

세 단계로 분리한 이유

  1. 원본 inventory는 전달받은 표제와 분류를 수정하지 않고 보존합니다.
  2. canonical catalog는 안정적인 concept ID, 별칭, 도메인, 문서 유형, 최신성 정책을 관리합니다.
  3. 작성 작업 큐는 실제 문서가 될 항목만 에이전트 하네스로 전달합니다.

이 분리 덕분에 프레임처럼 영상과 네트워크에서 뜻이 다른 항목을 성급하게 합치지 않고, 비트처럼 여러 도메인에서 같은 의미로 쓰이는 항목은 하나의 canonical concept로 재사용할 수 있습니다.

홈 화면에 1,157개 카드를 넣지 않습니다

홈과 위키 인덱스에는 도메인 요약과 최근 발행 문서만 출력합니다. 전체 카탈로그는 도메인별 JSON shard로 생성하고, 검색이 시작될 때 필요한 shard만 읽습니다.

빌드 결과의 크기보다 사용자가 처음 받는 HTML과 DOM의 크기를 먼저 제한합니다.

다음 단계

각 catalog 파일은 서로 다른 에이전트가 독립적으로 수정할 수 있습니다. 검색 인덱스, backlink, sitemap과 전체 그래프는 사람이 고치는 파일이 아니라 빌드 산출물입니다.
