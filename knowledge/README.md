# knowledge/ — 파생 콘텐츠 레이어 차터

AGENTS.md의 레이어 계약에 따라 채택된 **파생 자료(derived material) 레이어**다.
이 디렉토리는 위키의 편집 가능한 원본을 담고, 사이트가 서빙하는 검색 샤드는
여기서 **생성된 산출물**이다.

## English brief

Derived-content layer for the concept wiki. `catalog/` holds the editable
canonical catalog (one JSON array per domain); the public `search/wiki/*.json`
projection contains only `published` and actively authored `pending` records,
while `proposed` records remain internal. The shards and public manifest counts are regenerated by `scripts/build_search.py`
and gate-checked by the `catalog-sync` plugin. `guides/` holds authoring
blueprints for the ~1,157-document program. There is no external raw
inventory: the catalog (promoted from the search shards on 2026-08-03) is
itself the authoritative worklist that agents will turn into documents.

## 무엇이 들어오나

- `catalog/<domain>.json` — canonical concept 카탈로그, 도메인당 하나의 JSON 배열.
  **위키 개념 메타데이터의 단일 편집 지점.** 항목 스키마는 기존 샤드 스키마를
  그대로 따른다 (`type/id/title/aliases/status/kind/profile/summary/
  primaryDomain/domain/topics/route/url`). 공개 샤드는 검색에 필요한 필드만
  투영하며 내부 작성 taxonomy를 그대로 복사하지 않는다. 선택 필드 `atoms`(2026-08-05 확장):
  합성·상위 개념 항목이 구성 원자 항목의 id 배열을 기록한다 — 원자성 원칙과
  판정 절차는 `guides/atomicity-rubric.md`가 규범이다.
- `guides/` — 문서 작성 가이드라인, 시각화·테마 계약, 템플릿 청사진.
  1,157개 문서 프로그램에서 작성 에이전트가 읽는 규범 문서.

## 누가 편집하나

에이전트가 승인된 작업 단위 안에서 편집한다. `catalog/`의 항목 추가·수정은
파생 방향을 따르는 한 일반 작업이고, 스키마 필드 추가는 계약 변경으로
승인 절차를 거친다.

## 파생 방향

```
knowledge/catalog/<domain>.json          (원본 — 사람이/에이전트가 편집)
  → published/pending 공개 투영
  → search/wiki/<domain>.json            (빌드 산출물 — 편집 금지)
  → search/manifest.json 의 공개 counts  (빌드 산출물 — 편집 금지)
```

재생성: `python3 scripts/build_search.py` (검증만: `--check`).
게이트: `scripts/check.sh`의 `catalog-sync` 플러그인이 산출물 신선도를 강제한다.
산출물을 직접 고치면 게이트가 실패한다 — 고칠 곳은 언제나 `catalog/`다.

## 카탈로그가 곧 워크리스트다

외부에 별도의 inventory 원본은 존재하지 않는다 (사용자 확인, 2026-08-03).
`catalog/`의 항목들이 앞으로 작성해야 할 문서의 **권위 있는 작업 목록**이며,
에이전트들이 기존 발행 사례와 `guides/`의 청사진을 참고해 각 항목을 문서로
완성해 나간다. 항목의 `status`가 진행 상태를 추적한다. `proposed`는 일정과
착수가 확정되지 않은 내부 작성 대기 상태, `pending`은 실제 작성이 시작되어
공개 표면에서 **작성 중**으로만 보이는 상태, `published`는 발행 완료 상태다.
`published`만 완성 문서 링크를 가지며 `proposed`는 공개 샤드에 들어가지 않는다.

## 이 레이어가 아직 담지 않는 것 (명시적 부재)

- **문서 본문 원본** — 발행 문서(`wiki/**/index.html`)는 아직 HTML이 직접
  원본이다. 구조화된 문서 원본 포맷과 HTML 생성기는 후속 단위에서 도입할 수 있다.
- `search/content.json`(위키 외 페이지 검색 인덱스)은 이 빌드의 소유가 아니며
  당분간 수작업 유지된다.
