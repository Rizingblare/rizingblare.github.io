CASE STUDY / vat-query-v5

부가세 조회 V3 → V5 전환

검색 조건과 상태 분류를 새 화면 구조에 맞게 재설계

01

PROBLEM

구버전과 신버전에서 검색 조건의 이름과 의미가 달라 단순 필드 복사만으로는 동작하지 않았습니다.

발행 유형·전송 상태·메일 상태가 결합된 복합 조건을 화면 단위로 재분류해야 했습니다.

02

DECISIONS

  • 도메인 상태를 먼저 표준화한 뒤 화면의 상태 박스와 매핑했습니다.
  • 메뉴·프로그램별 분기 조건을 독립된 변환 함수로 나눴습니다.
  • 기존 SQL 별칭과 식별자는 유지해 회귀 위험을 줄였습니다.
03

OUTCOME

  • 신규 화면에서 기존 조회 의미를 유지하면서 조건 확장과 유지보수가 쉬워졌습니다.

공개 범위
고객사 정보와 사내 식별자는 공개하지 않고 문제 구조와 해결 원리만 정리했습니다.
